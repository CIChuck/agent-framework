package boundary; earlier Chat-dependent technical proposals are withdrawn.

### Decision process and evidence

The technical reasoning below records the earlier Chat-dependent proposal.
Its reusable-Chat seams and CD-TUI-001 sequence are withdrawn under D-08. Keep
the test results as historical baseline evidence, not as proof of an independent
TUI design.

Start with the fixed compatibility requirements, then inspect public source
interfaces and choose the smallest reusable seam. This ruled out moving CLI
components, replacing handlers and using global console activation for the TUI.

The original same-loop proposal was revised after inspecting synchronous file
reads inside async command handlers. A dedicated backend loop/thread preserves
their behavior while leaving the UI loop free. The cost is an explicit ordered
bridge and careful worker shutdown; thread cancellation cannot stop a write.

For Quit, the currently proven public safe boundary is the end of an admitted
operation. Waiting there and using input EOF reuses existing cleanup without a
new generic cancellation engine. The cost is waiting for slow operations; earlier
cooperative stopping remains a future owner-specific contract.

Dependency selection uses official metadata and an isolated resolution overlay,
not an installation into the shared environment. Current source baseline checks
passed 241 tests (155 CLI and 86 selected Chat), plus focused app/display Ruff
and Mypy. This does not claim a working Textual app or Linux UI validation.
See [retained technical evidence](validation/technical-evidence.json).

The maintainer's testing/UAT requirement is accepted. The withdrawn
[test-and-uat-plan.md](test-and-uat-plan.md) had proposed 24 units and five UAT
milestones spanning 14 scenario groups; CD-TUI-001 had split configuration
from shutdown. The [replacement plan](replacement-plan.md) now defines the
draft independent units and current UAT schedule. No unit execution or user
signoff is claimed.
