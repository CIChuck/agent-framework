## Findings

### INGEST-R1-SOL-001 — medium, mandatory: reconcile ownership of existing smart_read storage before claiming INGEST all-source completion

**Requirement:** settled all-source scope in discussion-decisions.json; REM D lines 367–440 and DI-19 require every storage handoff, including smart_read, to use shared policy and cache identity. Repository engineering policy requires explicit cross-package ownership. IR-07/08/13/16.

**Evidence:** REM lines 568 and 573 permit Memory's tool/large-file processors and Chat wiring, but not `filesystem/smart_read.py` or the Memory controller storage methods. REM 301–307 leaves legacy Tools entry-point adoption to the companion. TD 35–48 requires INGEST to establish and independently verify all-source behavior before TOOLS-DOC upgrades the named public consumers; TD 77–94 assigns their storage routing and cache correction to TOOLS-DOC.

Current `packages/friday-tools/src/friday_tools/filesystem/smart_read.py:593–625` directly calls `MemoryController.store_document(text=content, ...)` for small text files and caches the result; this bypasses `LargeFileProcessor` and `ToolOutputIngester`. Its session/long-term cache early returns at lines 280–318 also bypass processing. `controller/memory_controller.py:1918–1968` stores the supplied text as one document. Altering only the listed processors cannot reach this small-file handoff. The existing threshold is character-based and independent of the new token budget.

**Counterexample/risk:** an existing headless smart_read consumer with memory injected reads a text file smaller than 50,000 characters but exceeding 512 model tokens, with store_to_memory enabled. After only the listed INGEST changes, it still stores one unsplit input (or the global model guard rejects it); it does not implement document/512 or explicit recursive/fixed overrides. An old synthesis cache may skip that new path altogether. This is an ownership/sequence contradiction in the proposal, not a complaint that the current baseline is unimplemented.

**Narrow mitigation:** make an explicit planning decision assigning existing smart_read text-storage/cache changes to INGEST with a narrow allowlist addition, leaving four-format routing to the companion; alternatively make all-source completion a joint gate and explicitly bound what INGEST alone can claim. Retain the maintainer's final all-source requirement. Gate A should freeze the resulting handoff/consumer map rather than discovering two incompatible completion claims.

**Tests/doc impact:** preserve TD-02/05/10 and DI-19; explicitly place cold small-text, warm-cache, store-disabled→store-enabled and changed-budget/profile cases in the owning unit. Assert shared policy invocation/chunk provenance, correct opt-in behavior, no stale-cache bypass and no second split. Update REM/TD sequencing, exact paths and completion language together; no product repair requested in this review.

### INGEST-R1-SOL-002 — medium, mandatory: give persistent store/model binding an enforcement owner and a same-dimension reopen oracle

**Requirement:** REM 538–542 promises the same configured identity for indexing/retrieval and explicit store/model mismatch failure. IR-08/10/15/16 and policy's explicit contract rule apply. Fresh-store testing/no migration does not remove the need to enforce this promise on a later reopen.

**Evidence:** REM's owner table assigns ingestion policy to Memory and per-request capabilities to LLM, but no owner for persisted collection identity/read admission. Its exact path list includes new ingestion modules and Chat wiring, while REM 584–590 excludes storage-engine changes and requires a scope stop outside the list. Existing `packages/friday-memory/src/friday_memory/adapters/vector.py:82–92` opens/creates a collection with cosine configuration and no model fingerprint. Lines 99–109 delegate embeddings without collection identity. Query lines 223–232 accept an optional precomputed embedding; neither model identity nor a typed identity accompanies it. Core's `interfaces/memory.py` query contract likewise accepts an unqualified float vector. Per-chunk identity metadata does not by itself protect a query against the wrong collection. DI-18 tests model/counter and shape limits but does not explicitly require persistent store reopen/mismatch or unknown binding controls.

**Counterexample/risk:** populate a fresh disposable store with model revision A, close it, then reopen with revision B producing the same dimension and valid finite vectors. All length/cardinality/token checks pass; retrieval can compare incompatible vector spaces. A profile-name alias or formatting-revision change can cause the same problem. This is not legacy migration: it can happen entirely within the new disposable-store workflow.

**Narrow mitigation:** assign ownership of a durable embedding-space fingerprint and validation on create/reopen/read/write, identify the allowed seam (or explicitly approved scope adjustment), and specify unknown-binding refusal without scanning/resetting/re-embedding old stores. Bind the actual artifact/revision, output dimension and preparation convention, not just a mutable profile name. Clarify the treatment of precomputed query vectors. Exact signatures may remain gate-A work, but add these named gate-A deliverables and stop conditions now.

**Tests/doc impact:** add fresh-store create→reopen with matching identity PASS, same-dimension different artifact/revision/formatting FAIL, unknown fingerprint FAIL, and precomputed-vector admission controls; prove refusal before provider/storage/query side effects and unchanged bytes on refusal. Keep no-reset/no-migration requirements. Update owner/path and DI criteria; no migration implementation is requested.

REM 503–511 correctly requires a call-site audit and once-only query/document preparation.
