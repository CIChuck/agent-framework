B/N/R in the remaining maps describes ordinary baseline/replacement/refusal
**operations**, not a revived model campaign. It includes different dimensions,
same dimensions with changed preparation/declared identity, and reduced capacity.
Existing observed Nomic 768-dimensional/context-2048 evidence may inform a declared
test profile; it does not attest to any current server. Qwen remains illustrative.
No actual model call or switch is required by this offline construction plan.

A configured identity protects against declared model/revision/preparation/tokenizer/
dimension changes. It cannot detect an out-of-band server alias swap. Operators
must update the declared identity and select a fresh namespace when changing models;
no silent reset, stamp or migration is allowed. This limitation is explicit rather
than replaced by the removed serving-attestation prerequisite.

The activation labels **Gate A1–A5** are distinct from the council's **Review
A1–A8**. Gate A1 now binds these dispositions and existing evidence, Gate A2 the
exact design/assets, Gate A3 case exceptions, Gate A4 maintainer approval and final
impact satisfaction, and Gate A5 the isolated execution profile. None is complete
merely because a document council passes. Product acceptance follows construction.


For current exact implementation choices, the activation slice/case maps control
specific sub-exit assignments over the older phase-map shorthand: basic /read
content/refusal at I3-C3, responsiveness/cancellation/drain at I3-C4. Manifest
provisioning is an offline deployment binding (explicit resolver path or
FRIDAY_EMBEDDING_MANIFEST), with unchanged model YAML and no new model campaign.
It must be included in the final operator impact/guide and exact approval package.
The model-decision record's older "no new council follows" describes that earlier
preparation point; the later user-approved council authorization controls these
three review rounds. No technical parent or historical record is rewritten.


The current document settings binding is separate from the embedding manifest:
explicit API path, then FRIDAY_DOCUMENT_CONVERSION_MANIFEST. It supplies only
conversion assets/profile/scratch settings, can be used by /read with no Memory
or embeddings, and is unnecessary for plain-text reads. I3-C1/C3 owns its resolver
and composition, C4 its lifecycle, C5 installed/documentation acceptance. This
closes a construction-settings omission without adding Runtime YAML, new source
paths, asset downloads, vendor evaluation or serving-qualification gates.
