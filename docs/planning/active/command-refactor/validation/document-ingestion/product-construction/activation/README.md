## Slice boundaries

I1 adds Core/LLM/namespace/v2 foundation contracts while leaving legacy prepared
inputs and positive callers unchanged. I2 switches actual existing consumers,
origin/profile/task/error/recovery paths together and removes the temporary
unguarded branch. I3 adds one extraction/planning/embedding/storage path and actual
command/smart_read text adoption; TOOLS-DOC document routing remains separate.
Every slice needs its own applicable exact approval and independent implementation
validation. Final aggregate review precedes human UAT/acceptance.

The file map contains exact paths rather than the directive's shorthand. Its
source-unchanged witnesses are not edit permission. Existing optional new modules
are selected explicitly; no app.py or indirect-package product source expansion
is granted. The canonical approved impact is still
[assessment v0.6](../../../../package-impact-assessment.md), not this file map.
A post-qualification revision of that same assessment path remains required.

## Test changes and execution

The case map reads the existing inventory; it does not rebuild ASTs or rerun
Docling. Mapped exceptions are **proposals**, not permission to modify test bodies.
The concrete known changes cover invalid varying-dimension/unindexed LLM mocks,
explicit fresh/admitted store fixtures, and the fake-extension Chat document
positive. Actual former behavior remains positively tested with replacement
coverage; neither refusal nor preserved case counts prove compatibility.

No case is retired. Unlisted class/signature/assertion bodies and legacy helpers
stay unchanged. If a later slice requires another exception, map the exact old/new
node and valid assertions before approval/edit; no blanket fixture or assertion
waiver. Separate TOOLS-DOC owns its PDF-binary test exception. Retained SESSION/DIAG
fixtures and API54 stay unchanged. Six dual-role helper/fixture files keep one
identity and earn no extra test credit.

Validation selectors must be explicit because root discovery misses top-level
integration and Transcript/Finance `tests/` folders. Non-default offline selectors
are `packages/friday-transcript/tests/` and
`packages/friday-finance/tests/test_basics.py`. Finance's
`test_integration_massive.py` stays outside reading/parsing/execution and receives
no live-test credit. New fixture helpers and any other non-default module must be
classified before execution; an unclassified module is not presumed offline.
Tests using real embeddings need a separately bound provider/model window.
