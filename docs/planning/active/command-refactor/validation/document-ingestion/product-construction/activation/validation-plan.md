# INGEST activation — validation execution plan

Version 0.6, proposed A3/A5 plan. **No commands here were run as product validation.**
Only execute a phase after its exact approval and prepared isolated interpreter,
source snapshot, qualified assets and permitted effects have been bound. No
working `.venv`, dirty configuration or user `.friday*` store is a test target.
Use the existing isolation requirements; this is not a new package-resolution
harness or a repeat vendor efficacy benchmark.

## Required non-pytest evidence

- Focused root-rule Ruff/format and strict typing for changed public boundaries;
  record existing file-level ignores as debt and explicitly type-check new/moved
  public contracts without adding blanket ignores or weakening global settings.
- Dependency/default/headless/document profiles and Certifi floor after all
  installs, including installed origins; actual metadata/lock changes remain
  narrow. No unrelated package update or TLS verification bypass.
- Complete-content, dropped-tail/order, role/count, stale receipt/source/profile,
  index/dimension, foreign identity, namespace fallback, worker late-output and
  v1/v2 mixed-artifact controls fail at the required assertion/call boundary.
- At I3-C4 apply the exact worker threshold table, Runtime public registration/
  close and Chat real-application cancellation/drain witnesses. No such finished
  worker proof is required to approve I1/I2 construction.
- Every mapped old case retains its valid oracle or obtains executed replacement
  coverage. Fixture/synthetic model qualification is labelled honestly; it is not
  real serving parity or general retrieval-quality evidence.
- Canonical architecture and affected guide/README sections are substantively
  authored, with changed requirement → source → document → verified example map.
  Link/metadata checks supplement that review. Distinguish all three registries,
  actual Chat versus placeholder CLI entry points, package extras, model readiness,
  explicit fresh-store upgrade and test-only/provider-window boundaries.

Finance live integration and LLM live LM Studio tests remain excluded from default
execution; no credential is read or copied. All effects, costs, provider/window
and test roots must be explicit in A5. Known baseline failures remain recorded

remain subsequent gates.
