# Focused review context — implementation directive

These are scope facts from the governing documents and maintainer decisions,
not a claim that the directive is complete or a substitute for independent review.

- Review the main directive in full. Docling is the evaluated choice; its measured
  configured profile and limitations are established input. Decide whether Friday
  will correctly integrate it, not whether to evaluate/install Docling again.
- The intended file formats are PDF/DOCX/XLSX/PPTX, with local PDF OCR. The common
  ingestion policy covers all supported inputs: document/512 defaults, independent
  overrides, document/recursive/fixed strategies and guarded prepared-input limits.
- Qwen4B remains illustrative. Preserve existing embedding selection/configuration
  interfaces; a new embedding space needs deliberately selected coherent fresh
  state. No migration, store reset or production model selection is authorized.
- I1 supplies neutral contracts/LLM/namespace foundations; I2 wires existing
  consumers without breaking them; I3 supplies extraction/common planning/file
  commands/cache and document dependency adoption. Assess that order and the
  completeness of its duties. A2/A3 exact artifacts remain explicit future gates.
- Eight implementation owners are Core, LLM, Memory, Tools, Commands, Chat, Runtime
  and conditional CLI. Assess all17 package dispositions in the approved impact
  table, including indirect consumers, without auditing unrelated algorithms.
- Separate TOOLS-DOC owns public factory/smart_read document adoption; INGEST
  owns the shared converter/common path and existing smart_read text storage/cache
  duties. Neither unit may claim the other's completed consumer integration.
- Test migration and substantive architecture/guide rewrites are implementation
  deliverables. Judge whether meaningful acceptance proves actual Friday
  command→chunks→embeddings→store behavior, failures and compatibility. Existing
  test inventories are reference inputs; rebuilding them is not this review.
- Construction, actual integration validation, separately authorized model windows,
  human UAT and delivery remain future gates. Their absence is not a failed
  Docling result or authority to implement during council.
