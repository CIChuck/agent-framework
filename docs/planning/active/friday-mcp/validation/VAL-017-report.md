## Numbered findings

1. **VAL-017-F01 — High severity: the guide promises nonfatal optional failure for its own configuration, but startup fails.** `docs/guides/17-mcp-client.md:17-32` selects `mcp_demo_probe` by explicit `include_tools` while setting `required: false`. Lines 60-63 then say a failed optional peer keeps other providers available. `docs/guides/10-configuration.md:2158-2161` likewise describes the optional failure as diagnostic. In the accepted runtime, `_selected` and `prepare_registration` require every explicit include to be registered (`packages/friday-runtime/src/friday_runtime/mcp_registration.py:440-451,568-576`); `RuntimeMCPProvider.register_tools` converts an unsatisfied include into `ToolProviderLoadError` (`mcp_loading.py:221-249`). My independent local probe changed only the guide server's command to `/no-such-val017-command`, retaining `required: false` and the explicit include. Discovery recorded `connection_failed`, then registration raised `MCP registration failed (missing_include)`. **Risk:** an operator following the principal example may expect Chat/native providers to remain available when the optional peer is down, but startup stops. **Mitigation:** explain that an explicit missing include is fatal even for an optional server, and demonstrate a configuration that genuinely continues after an optional failure if that behavior is being recommended. **Regression/verification coverage:** rerun the exact local bad-command probe through start *and* registration, plus the good-peer and required-failure probes; parser-only checks cannot catch this lifecycle interaction. **Documentation/config impact:** update the MCP guide's optional/required prose and the configuration/troubleshooting summaries; no runtime behavior or config schema change is requested. This blocks WS08-AC01 and WS08-AC03.

2. **VAL-017-F02 — Low severity: the configuration summary excludes a supported selected-mode filter.** `docs/guides/10-configuration.md:2158-2159` says selected mode needs explicit canonical `include_tools` names. `_selected` also admits `include_categories: [mcp]` with no `include_tools` (`mcp_registration.py:440-451`), as the new guide acknowledges at `17-mcp-client.md:41-44`. An independent local stdio probe with `mode: selected`, `include_categories: [mcp]`, and empty `include_tools` registered `mcp_demo_probe`. **Risk:** a reader may reject a valid existing selected-mode configuration or infer an unnecessary migration. **Mitigation:** qualify the summary to name `include_categories: [mcp]` as an alternative selection rule and retain the canonical-name guidance for `include_tools`. **Regression/verification coverage:** parse the category-filter configuration in Runtime and Chat, then repeat the local registration probe with no tool-name includes. **Documentation/config impact:** wording only in `docs/guides/10-configuration.md`; no template, schema or runtime change is requested. This affects WS08-AC01 accuracy.
