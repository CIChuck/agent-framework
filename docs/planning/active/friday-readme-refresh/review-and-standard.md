The shared structure is purpose/role, distribution/import/Python status, installation, useful quick start where implemented, configuration and boundaries, focused development commands, deeper docs/support and license. Root additionally maps all distributions and distinguishes installing an app/library from developing the uv workspace. Common structure does not mean identical length or invented usage for placeholders.

Research basis: [GitHub README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) emphasizes purpose, usefulness, getting started, support and contributors; [PyPA project metadata](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/) establishes each README as its distribution long description; [PyPA rendering guidance](https://packaging.python.org/en/latest/guides/making-a-pypi-friendly-readme/) supports render validation; [uv workspaces](https://docs.astral.sh/uv/concepts/projects/workspaces/) defines member selection and shared-lock behavior. [AutoGen Core](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-core/README.md) and [LangChain Core](https://github.com/langchain-ai/langchain/blob/master/libs/core/README.md) were inspected as examples, not mandatory templates.

Cross-repository/package documentation links use canonical absolute GitHub URLs to remain meaningful on PyPI as well as GitHub. Directory links use tree URLs; file links use blob URLs. Source/guide targets are checked locally at the candidate; unpublished new text is not assumed present on the remote branch. No documentation edits alter the already-published alpha3 artifacts or PyPI descriptions.

Validation: 22 Python fences compile, 18 offline example/CLI scenarios pass, and 167 README links were checked. Four explicitly live examples were compiled/inspected but not executed. All17 Markdown descriptions render.
