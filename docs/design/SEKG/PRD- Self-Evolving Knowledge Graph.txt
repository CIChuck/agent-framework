Product Requirements Document: Self-Evolving Knowledge Graph (SEKG)Project: Friday Agent FrameworkModule: friday-memoryVersion: 2.2Status: Approved for Design1. Executive SummaryThe Self-Evolving Knowledge Graph (SEKG) is the long-term semantic memory engine for the Friday agent. It addresses the critical limitations of vector-based Retrieval-Augmented Generation (RAG) by enforcing a structured, logical representation of information.Unlike static knowledge graphs that require manual ontology engineering, the SEKG is designed to be autopoietic (self-creating). It ingests unstructured conversation data, extracts logical triples (Subject-Predicate-Object), and automatically "morphs" its underlying schema based on the frequency and stability of new information. This allows the Friday agent to learn domain-specific jargon, organizational hierarchies, and complex relationships without explicit human programming, providing a deterministic "Source of Truth" that evolves alongside the user.2. Problem StatementContext Drift in RAG: Vector similarity searches frequently return irrelevant results because they lack a structural understanding of relationships (e.g., failing to distinguish between "Friday the Assistant" and "Friday the day of the week").Schema Rigidity: Traditional ontologies (OWL/RDF) are brittle. They require predefined classes and properties, making them unsuitable for dynamic domains where terminology shifts rapidly.Lack of Deep Reasoning: Current LLM assistants cannot reliably answer multi-hop questions (e.g., "Who owns the company that developed the project I worked on last week?") because this requires traversing a graph, not just matching keywords.3. Output: (Chuck, created, Friday)  Must handle zero-shot extraction without pre-training.US.2SystemAs the Gatekeeper, I want to validate new triples against a set of baseline logic constraints before storing them.If created has Domain: Person and Range: Product, then (Rock, created, Friday) must be flagged or rejected if "Rock" is not a Person.US.3SystemAs the Morphing Engine, I want to detect when a new relationship type appears frequently and promote it to the Core Ontology.Promotion requires Evidence Score > Threshold (not just raw count). Logic: Find Chuck -> founded -> Company -> employs -> Employee.US.5SystemAs the Reconciliation Agent, I want to merge synonym nodes to prevent knowledge fragmentation, with the ability to undo the operation.The system must merge Corp. and Corporation but retain a version snapshot to allow a manual "Unmerge" if the decision was incorrect.US.6UserAs a User, I want the system to ask for clarification when a new fact is ambiguous.If the user says "Friday is slow," the system asks: "Do you mean the software framework or the day of the week?"US.7DeveloperAs a Maintainer, I want to visualize the graph's evolution over time.A visual export (e.g., DOT/GraphViz) showing which nodes/edges were added in the last session.4. Logical ArchitectureThe SEKG is composed of four distinct processing engines that function in a continuous loop.4.1. Universal Extraction Engine ("The Triplicator")Responsibility: Converts unstructured text into structured graph data.Logic:Ingests raw text from the Friday conversation loop.Performs Zero-Shot Triple Extraction to identify Entities and Relations.Tags every extraction with a confidence_score (User Input = 1.0, LLM Inference = 0.5) and a timestamp.Output: A stream of "Candidate Triples" sent to the Gatekeeper.4.2. Structural Gatekeeper ("The Validator")Responsibility: Ensures the logical integrity of the graph.Logic:Fast-Path Validation: Uses SHACL-like (Shape Constraint Language) validation to check structure and type constraints without invoking a full reasoner. This ensures validation occurs within the <200ms latency budget.Deep-Path Validation: Asynchronous batch process using OWL-DL reasoning to check for deeper logical inconsistencies (e.g., circular class hierarchies) during idle time.Output:Valid: Passed to Staging.Invalid: Rejected.Ambiguous: Triggers a clarification prompt to the User (US.6).4.3. Morphing & Discovery Engine ("The Evolution Layer")Responsibility: Manages the expansion of the schema from "Staging" to "Core".Logic:Evidence Counter Algorithm: Implements a temporal decay function to calculate the "Truthiness" of a fact over time.Formula: $E(t) = \sum (C_i \times e^{-\lambda(t - t_i)})$$C_i$: Confidence of mention $i$ (User=1.0, Passive=0.5).$\lambda$: Decay rate (e.g., half-life of 7 days).Promotion Triggers:$E(t) > Threshold$ (e.g., 5.0) AND$Span(t_{last} - t_{first}) > D_{min}$ (e.g., > 1 hour) to prevent "hallucination bursts" from a single conversation turn.4.4. Semantic Reconciliation Agent ("The Janitor")Responsibility: Deduplication and graph hygiene.Logic:Runs as an asynchronous background task.Uses Vector Embeddings to calculate cosine similarity between node labels.Rollback Mechanism: Every merge operation (e.g., collapsing "Dev" into "Developer") creates a Transaction Snapshot. This allows the user or administrator to execute an undo_merge() command if distinct entities were incorrectly conflated.5. Integration with Friday FrameworkThe SEKG will be implemented as a standalone Python package: friday.memory.Interface:friday.memory.ingest(text: str): Entry point for the extraction loop.friday.memory.query(sparql: str): Interface for the Assistant to retrieve knowledge.friday.memory.reason(question: str): Higher-level method that converts natural language to graph queries.Storage:Filesystem: Local .owl (Ontology) and .sqlite (Triples) for single-user deployments.In-Memory: NetworkX graph for rapid reasoning during active sessions.6. Opportunities, Risks, and DifficultiesOpportunitiesDomain Agnosticism: The system starts generic but becomes a specialist (Legal, IT, Medical) purely through interaction.Explainability: Unlike black-box embeddings, every answer derived from the SEKG can be traced back to a specific triple and source interaction.RisksSemantic Pollution: If the Gatekeeper is too loose, the graph will fill with noise (slang, typos), degrading retrieval quality.Performance Latency: Real-time graph reasoning is computationally expensive. Validation must occur <200ms to maintain conversational flow.Irreversible Merges: Incorrectly merging entities (e.g., two people with the same name) can destroy data integrity. (Mitigated by US.5 Rollback).Difficulty AssessmentOverall Complexity: High (8/10).Primary Challenge: The Morphing Engine. Algorithmic determination of when to "harden" a temporary fact into a permanent ontology class is a non-trivial research problem.7. Success MetricsRecall Precision: >90% accuracy in retrieving specific entity attributes (e.g., "What is Chuck's role?") compared to <60% for standard RAG.Schema Convergence: The rate of new schema creation should decay over time as the system "learns" the domain, stabilizing after ~500 interaction turns.Deduplication Rate: The Reconciliation Agent should reduce total node count by >30% compared to raw extraction.Rollback Rate: <5% of automated merge operations should require manual rollback by the user.
