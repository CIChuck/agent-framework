System Design: massive-agent-core1. Class Hierarchy & ArchitectureThe package follows a "Manager-Client" pattern. A central MassiveClient coordinates specialized modules, ensuring that all requests flow through a unified rate-limiter (The Governor).1.1. Core ComponentsMassiveClient: The entry point. Manages authentication, session lifecycle, and tier detection.MassiveGovernor: An asynchronous token-bucket implementation.Registry: A lookup table for Index and Bond ETF proxies.BaseModule: An abstract class ensuring consistent error handling across Equities, Crypto, and Indicators.2. Tier Sensitivity LogicUpon initialization, the client performs a "Tier Probe" (a low-cost call to the Reference API).If Free: The Governor sets RPM = 5 (12.0s interval).If Starter: The Governor sets RPM = Unlimited (switching to a 0.01s safety delay to prevent burst-related socket errors).3. Data Flow DiagramAgent Tool Call -> client.equities.get_summary("AAPL")Governor Check -> await governor.wait() (Sleeps if bucket is empty)SDK Request -> massive.RESTClient.get_aggs(...)Data Enrichment -> Join price data with Registry metadata.JSON Return -> Returns a clean dictionary to the Agent Framework.4. Market Day ResolutionWe implement a Calendar utility that uses pandas.tseries.offsets.CustomBusinessDay. If a query hits a weekend/holiday:Stocks: Roll back to the previous Friday.Crypto: Bypass calendar logic (24/7).5. Model Integration (Risk On/Off)The Indicators module will specifically support the "Risk On/Off" models mentioned.Risk On/Off Signal: A computed property comparing SPY (Risk On Proxy) vs. AGG (Risk Off Proxy) using relative strength and SMA crossovers.
