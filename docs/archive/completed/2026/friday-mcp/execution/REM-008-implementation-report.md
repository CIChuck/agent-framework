Memory finds a validated owned snapshot by the actual transcript entry ID and per-call ID across collection stages. Its locked stage path rejects a second record for the same ownership. The ingester reuses the original durable snapshot and captured timestamp only after matching complete checked call provenance, policy, grant, sanitized text and storage facts; a conflicting owned record raises a fixed safe error. A failed or cancelled uncertain stage leaves any existing pending record excluded, so a competing retry cannot delete it. Public Chat preparation uses this lookup without embedding or writing again.

The transcript adapter reads the immutable entry through the public store API and checks session, user/assistant messages, model/temperature, persisted timing/context metadata, every native and MCP call ID/name/arguments, every paired output/error and all safe execution provenance. The coordinator checks the exact receipt and the owned memory snapshot/policy before returning the original paired facts. A successful append retry returns immediately without another append. If append reports an ambiguous failure, only a matching complete public readback can settle it; false append or failed readback raises a fixed safe persistence error. A matching receipt can publish its still-pending record after a prior publication failure. A conflicting payload, provenance or policy cannot overwrite the entry or record. Cancellation propagates; no detached work is started. Legacy/custom adapters retain the optional-capability skip path, and native-only turns retain their existing path.
