## Numbered findings

### 1. VAL-011-F-001 — High — MCP runtime environment values are persisted and exported through session snapshots

**Observed requirement violation.** A successful public MCP turn with a configured synthetic server environment value causes the production transcript adapter to persist the complete MCP configuration in `TranscriptSession.config_snapshot`. The value then appears in the JSONL session header, including when `include_metadata=False`. Public `CSVExporter.export_all_sessions` also copies it into `sessions.csv`. Single-session CSV entry export, its `entries.csv` companion and Markdown session export did not expose this value in the probes. The finding concerns a known configured MCP runtime-sensitive input; it does not demand arbitrary secret classification or rewriting user/LLM prose.

**Authority.** WS05-AC02 explicitly requires that no env/header sentinel survive MCP-owned persistence/capture boundaries; WS05-AC07 requires safe production records; WS05-AC08 governs safe exports. The approved build plan, lines 118–120, says secret-bearing `env`, headers, command arguments, URLs and tool-call arguments are runtime-only input. WS-05 owns persistence/redaction enforcement (build plan 659 onward), and the directive's failed-call contract also forbids retained env/header/secret-bearing messages (159–170). The successful-turn reproduction alone establishes the general runtime-only snapshot violation. Configuration/SQLite schema redesign and later telemetry features remain outside scope.

**Affected sources.** `packages/friday-chat/src/friday_chat/adapters.py:1313–1324`, especially line 1323, passes `self.config.model_dump(mode="json")` directly to session creation. `packages/friday-transcript/src/friday_transcript/exporters/jsonl.py:68–74,162–175` writes that snapshot in the session header; the entry-only metadata flag logic at 178–205 does not remove it. `packages/friday-transcript/src/friday_transcript/exporters/csv.py:178–223,238–251,277–291` exports the same snapshot in the existing session CSV column.

**Inherited versus new.** The same successful-turn snapshot leak and all three exposing surfaces reproduce on the full approved work-unit base using archived original-source imports. This is inherited behavior, not a new line-level WS-05 regression. It nevertheless violates WS-05's explicitly approved aggregate runtime-only/no-sentinel persistence requirement and has no declared waiver. The allowed adapter/export paths make a bounded repair possible without changing configuration or storage schemas. Existing accepted predecessor status does not supersede this new work-unit criterion.

**Executable reproduction.** Run `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python /private/tmp/VAL-011-independent-20260928/run_findings.py` from the repository after extracting the archived approved base as documented in `baseline.py`; this runner launches exact candidate and baseline source imports and a real synthetic stdio peer. Inspect `finding-results-candidate.json` and `finding-results-baseline.json`: `session_config_contains_env_value: true` and `exported_by: ["JSONL", "JSONL metadata false"]` in each. Then run the archived `export_all_repro.py` runner to observe `sessions_csv_contains_configured_env_value: true`, `entries_csv_contains_configured_env_value: false` on each. These diagnostic commands exit 0 when recording observations, not when requirements pass. The asserting public matrix exits 1 on all four production combinations (streaming/nonstreaming × normal/fallback); fake-adapter counterparts pass. The peer audit verifies original configured env reached execution without preserving its value in the audit.

**Risk and severity.** High: runtime-configured MCP environment credentials may become durable transcript state and travel in ordinary transcript exports. Disabling entry metadata does not protect the session header. No real credential was used; the probe's only sensitive-like value was the synthetic sentinel `VAL11_ENV_HEADER_MARK`.

**Concrete mitigation boundary and regression expectations.** Sanitize or omit MCP runtime-sensitive configuration values at the consumer's persisted session-snapshot boundary while preserving original runtime execution inputs. Maintain safe native configuration/metadata compatibility and existing CSV columns/privacy controls. Cover the explicitly documented runtime-sensitive surfaces (at minimum env values; configured command arguments can also hold secrets) without general configuration redesign, new settings, argument hashes or a historical DB migration. If older already-stored snapshots need export-time treatment, the controller/maintainer must bound that behavior explicitly. Verify a real peer receives original env/arguments; no synthetic configured value reaches session/entry SQLite JSON, raw/context capture, JSONL with metadata on/off, all-session CSV, entry CSV or Markdown, in both actual turn modes and fallback paths. Preserve old/native models and exporter contracts. Update the bounded implementation report to state the tested snapshot policy accurately.

### 2. VAL-011-F-002 — High — A later native call-ID collision leaves ambiguous continuation and newly prevents turn persistence

**Observed requirement violation.** An MCP call in the first tool-loop iteration with valid ID `later-native`, followed in the next iteration by a native `echo` call with the same ID, produces two continuation tool messages with identical `tool_call_id`. Their distinct records cannot satisfy the new MCP transcript pairing validator. With the real production adapter the completed turn raises `TurnPersistenceError`, adds zero transcript entries, and retains ambiguous IDs in the final model continuation. Both actual calls executed.

**Authority.** WS-05 directive 105–113 requires distinct mixed/repeated per-call facts and coherent unique MCP IDs while preserving native IDs; 178–194 requires paired compatible transcript persistence. WS05-AC06 and WS05-AC07 are violated; WS05-AC09's native/mixed compatibility is also affected. The request explicitly requires native collisions **across iterations**. Resolving only the current response's native IDs does not meet that requirement.

**Affected sources.** `packages/friday-chat/src/friday_chat/tools/loop.py:79–114` reserves native IDs appearing in the current response before allocating MCP IDs. `packages/friday-chat/src/friday_chat/turns/processor.py:452–481` shares a used-ID set across iterations but never repairs an earlier MCP ID when a future native call retains it. `packages/friday-transcript/src/friday_transcript/models/transcript.py:263–294`, particularly 277–289, correctly rejects ambiguous MCP call/result pairing. `packages/friday-chat/src/friday_chat/adapters.py:1141–1177` submits the records, and `turns/processor.py:548–598` wraps the validator failure as turn persistence failure. Weakening the validator would hide the upstream correlation fault.

**Inherited versus new.** The archived approved-base turn also has duplicate continuation IDs, but successfully persists one new entry. The candidate still has the inherited ambiguous continuation behavior and additionally raises persistence failure because of its new strict typed pairing validation. The regression is therefore the failed previously persistable turn; the approved WS-05 handling must also eliminate the inherited ambiguity rather than accept duplicate IDs. This exact distinction is independently captured with original-source imports in the two reproduction fact files.

**Executable reproduction.** The same `run_findings.py` runner builds actual TurnProcessor, production SQLite adapter and a real peer. Model iteration 1 requests `mcp_alpha_probe_run` with `{}` and ID `later-native`; iteration 2 requests native `echo` with `{"text":"native benign"}` and the identical ID; iteration 3 returns `done`. Candidate facts show `exception_type: "TurnPersistenceError"`, `continuation_tool_ids: ["later-native", "later-native"]`, `persisted_entries_added: 0`. Baseline facts show no exception, identical ambiguous IDs and one added entry. The asserting independent `test_cross_iteration_native_collision` fails on the candidate. Same-response native reservations, repeated MCP IDs, missing/invalid IDs, repeated tool names, concurrent peer calls and metadata association separately pass.

**Risk and severity.** High: a permitted mixed tool turn that completes its executions can fail transcript persistence, and the model cannot unambiguously associate subsequent tool results. Loss of the durable turn and incoherent per-call provenance violate core WS-05 behavior. No source fix was attempted.

**Concrete mitigation boundary and regression expectations.** Resolve IDs across the entire turn while retaining native-ID behavior. If a later native request collides with an earlier MCP ID, reassign the affected MCP ID and atomically update its retained assistant request, tool-result message, typed record/provenance and all relevant continuation/capture/history copies before subsequent model capture or persistence. Do not weaken paired validation, drop records, accept duplicates, rewrite native IDs or invent entry correlations. Add actual streaming/nonstreaming, fake/production, three-iteration preceding-MCP/later-native cases, repeated MCP names/IDs, multiple servers and concurrent calls. Assert every assistant request/result/record has coherent unique MCP identifiers, actual persisted entry IDs remain consistent, native IDs are preserved and the previously completed mixed turn stores successfully without migration. Existing same-iteration invalid/missing/duplicate/native collision tests must continue passing.

## Artifact manifest and byte preservation

`evidence.json` enumerates every archived report/source/script/log/probe/wheel/input member with exact byte size and SHA-256. The manifest excludes itself from its own member hash list; `delivery.json` gives its exact hash, the report hash and archive hash. Archive-member set integrity and each decompressed member hash were independently checked after packaging. Archive members preserve original bytes; deterministic tar ownership/timestamps affect only container metadata. Original scripts and full logs, including intermediate scratch failures, are included. Runtime databases, cache/venv trees, extracted product trees, temporary export files and unrelated artifacts are deliberately omitted. The controller can preserve the full report byte-for-byte without editing its portable member references.
